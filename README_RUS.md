# vidx

[English](README.md) · **Русский**

Достаёт картинки и текст из видеофайла или ролика YouTube (любой ссылки, которую понимает yt-dlp).
Прогоняет все локальные распознаватели речи, доступные на Apple Silicon, распознаёт текст на экране и
сводит всё в одну расшифровку. Всё работает на самом Mac: аудио и видео никуда не отправляются.

Сделан для длинных записей созвонов на русском с демонстрацией экрана; работает с любым языком,
который знает whisper, и с видео, где речь переключается между русским и английским.

```bash
vidx setup                                         # один раз: инструменты + ~13 ГБ моделей
vidx ~/Downloads/meeting.mp4 --meet -j 3           # → ./meeting_vidx-out/transcript.md
vidx "https://www.youtube.com/watch?v=VIDEO_ID" -g glossaries/example.txt
vidx find meeting_vidx-out 'kubernetes|helm'       # фраза → таймкод
vidx help run                                      # все опции
```

Нужно: macOS 26+ на Apple Silicon (MLX, SpeechTranscriber), Homebrew, Xcode command line tools
(`swiftc`). Чтобы вызывать из любой папки: `ln -s "$PWD/vidx" ~/.local/bin/vidx` (любая папка из `PATH`).

## Как это работает

```
вход ─► 1 источник ─► 2 аудио ─► 3 язык ─┬─(смешанная речь)─► parakeet ─► языковые участки ─┐
                                         └─────────────────────────────────────────────────┤
                                                                                           ▼
                               очередь задач (-j N):  4 распознаватели речи  │  5 кадры ─► OCR
                                                                                           ▼
                                                                                    6 склейка
```

Каждый шаг пишет результат в папку вывода — по умолчанию `./<имя>_vidx-out/` в текущей папке
(`-o` меняет её). Рядом с каждым результатом vidx сохраняет опции, с которыми он получен
(`.vidx/<файл>.params`). Шаг пропускается, если результат есть **и** получен с теми же опциями, поэтому:

- прерванный запуск продолжается с места остановки: незавершённые шаги не записали отметку и
  выполняются заново;
- смена опции перезапускает только зависящие от неё шаги (`--scene` переделывает кадры и OCR, `-l` —
  движки, привязанные к языку, `-g` — whisper);
- `-f` переделывает всё, включая скачивание.

`.vidx/` ещё и помечает папку как созданную vidx: `-o` откажется писать в непустую папку без этой
пометки, так что vidx никогда не перезапишет и не удалит чужие файлы. Другой входной файл или ссылка
в той же папке — работа начинается заново.

### 1. Источник

- **Локальный файл**: подключается симлинком `source.<ext>`, не копируется.
- **Ссылка**: yt-dlp скачивает видео (≤ 1080p, `--max-height`), `info.json` (название, главы, язык),
  `description.txt` и `thumbnail.jpg`. Из ссылки на плейлист берётся только одно видео; конфиги
  yt-dlp игнорируются (`--ignore-config`).
- **Субтитры YouTube**: ещё два прохода yt-dlp — отдельно ручные и автоматические, чтобы они попали в
  разные файлы (`subs/manual.ru.json3`, `subs/auto.en.json3`). Запрашиваются только дорожки на языке
  оригинала: ru, en, языки из `--lang` и язык самого видео, плюс их варианты `-orig`. Без этого
  списка YouTube отдаёт десятки машинных переводов. `--sub-langs` задаёт список вручную.
  Для видео на двух языках скачиваются обе дорожки, ru и en, если они есть. Но автосубтитры YouTube
  делаются только на одном языке (основном языке видео), поэтому второй язык в них искажён; при
  склейке каждая дорожка используется только на участках своего языка, остальное закрывают
  распознаватели речи.

### 2. Аудио

ffmpeg → `audio.wav`, 16 кГц, моно, 16-битный PCM — формат, который ждут все движки. Файл сначала
пишется под временным именем и переименовывается, когда готов. Если в файле нет звуковой дорожки,
работа останавливается с понятным сообщением; `--no-asr` пропускает шаги 2–4 и даёт только картинки
и OCR.

### 3. Язык

`--lang` принимает `auto`, один язык (`ru`) или список (`ru,en`).

`auto` ([lib/detect_lang.py](lib/detect_lang.py)): whisper turbo определяет язык равномерно
разнесённых 10-секундных отрывков, по одному на минуту записи (от 5 до 30 отрывков). Самый частый язык
берётся всегда; ещё один — только если он выиграл хотя бы 2 отрывка **и** 20 % от всех, чтобы одна
ошибка не делала видео смешанным. Если речи нет вовсе — `ru`. Результат кэшируется в `lang.txt`.
Поэтому короткие видео и короткие переключения (один вопрос на английском посреди русского созвона)
смешанными не определяются: укажите `-l ru,en` явно.

Русская речь с английским жаргоном (Kubernetes, деплой, Jenkins) — **не** смешанная: используйте
`ru` и глоссарий. Смешанная — это целые куски на разных языках.

**Языковые участки (только для смешанной речи).** Движки, которым задан язык, плохо работают на
другом: whisper с `--language en` *переводит* русскую речь на английский, а GigaAM превращает
английскую речь в бессмыслицу латиницей. Поэтому до очереди задач:

1. Запускается parakeet (ему язык не задаётся, он понимает оба).
2. [lib/regions.py](lib/regions.py) помечает каждое предложение parakeet по алфавиту: кириллических
   букв больше, чем латинских → ru, иначе — второй язык из списка. Предложения без букв наследуют
   предыдущую пометку. Так отличается кириллица от латиницы, но не английский от немецкого.
3. parakeet часто теряет пару секунд ровно там, где говорящий переключает язык. Каждому разрыву
   длиннее 1 с язык определяет whisper turbo по самому звуку; короткие или тихие разрывы делятся
   между соседями.
4. Подряд идущие куски с одинаковой пометкой становятся участком → `regions.json`
   (`[{start, end, lang}]`).

На тестовом видео (русский 0–21,7 с, английский 21,7–39,1 с, дальше русский) участки получились
0–21,4, 21,4–38,9, 38,9–конец. Если parakeet или разбиение падают, работа продолжается только с первым
языком из списка.

### 4. Распознаватели речи (очередь задач)

Каждый движок пишет `asr/<имя>.json` — список сегментов `{start, end, text}`. При смешанной речи
движки, которым задаётся язык, запускаются по разу на каждый язык и получают суффикс `@язык`
(`whisper-large-v3@en`); whisper и turbo при этом распознают только участки своего языка
(`--clip-timestamps`), GigaAM — только русские участки. Vosk и Apple работают по всему файлу; при
склейке их текст вне своего языка не используется.

| Движок | Модель | Язык | Где считает | Заметки |
|---|---|---|---|---|
| whisper | whisper-large-v3 (mlx-whisper) | задаётся, по разу на язык | GPU | подсказка из глоссария, `--condition-on-previous-text False` против зацикливания |
| vosk | Kaldi vosk-model-ru-0.42 / en-us-0.22 | по разу на язык (ru, en) | CPU | модели скачиваются при первом использовании; примерно в реальном времени |
| gigaam | GigaAM-v3 e2e_rnnt (Сбер) | только русский | GPU (MPS) | см. ниже |
| parakeet | parakeet-tdt-0.6b-v3 (parakeet-mlx) | любой из 25 европейских, не задаётся | GPU | сам режет на куски по 120 с; при смешанной речи запускается первым и задаёт участки |
| apple | macOS SpeechTranscriber | по разу на поддерживаемый язык | Neural Engine | русского нет, для ru пропускается |
| turbo | whisper-large-v3-turbo | задаётся, по разу на язык | GPU | запасной вариант whisper |

**GigaAM** не принимает аудио длиннее 25 с, поэтому [lib/gigaam_run.py](lib/gigaam_run.py) режет его
сам: меряет громкость каждого 30-миллисекундного кадра, режет в самом тихом месте через 14–22 с после
предыдущего разреза и так до конца; тихие куски пропускаются, каждый кусок распознаётся отдельно. При
смешанной речи режется каждый русский участок отдельно, так что ни один кусок не пересекает смену
языка. Кусок с ошибкой пропускается; если упали все — движок считается упавшим.

**Vosk** ([lib/vosk_run.py](lib/vosk_run.py)) получает аудио порциями по 0,5 с и сохраняет сегмент
каждый раз, когда Kaldi закрывает фразу.

**Параллельный запуск.** `-j N` выполняет до N задач одновременно (по умолчанию 1 — по очереди).
Очередь устроена так, что работа на GPU и CPU чередуется: whisper (GPU) · vosk (CPU) · кадры + OCR
(CPU) · gigaam · parakeet · apple · turbo. Поэтому уже `-j 2` совмещает самые долгие задачи на GPU и
CPU, а `-j 3` добавляет кадры. При `-j > 1` вывод каждой задачи идёт в `logs/<задача>.log`, а в
терминале видны только старт, завершение и ошибки (с последними строками лога). При смешанной речи
parakeet и разбиение на участки выполняются до очереди: GigaAM и whisper нужны участки. Ctrl-C
останавливает все запущенные задачи.

Упавшая задача не останавливает работу: остальное склеивается, упавшие задачи перечисляются в конце,
и vidx завершается с кодом 3.

Ограничение — память: whisper large-v3 нужно около 4 ГБ, Vosk ru — около 6 ГБ RAM, parakeet и turbo —
по 2–3 ГБ, GigaAM — около 1 ГБ. На Mac с 24 ГБ комфортно `-j 3`, на 16 ГБ — `-j 2`.

### 5. Кадры и OCR (очередь задач)

Одна задача, [lib/frames.py](lib/frames.py) и [lib/ocr.swift](lib/ocr.swift):

1. **Захват**: один проход ffmpeg сохраняет кадр, когда сцена меняется сильнее `--scene` (0,3) или
   когда с последнего сохранённого кадра прошло `--every` секунд (10). Время каждого кадра даёт
   фильтр ffmpeg `showinfo`. Сырые кадры складываются во временную папку.
2. **Отсев дублей**: каждый кадр уменьшается до серой миниатюры 240×135 и сравнивается с 6
   последними оставленными кадрами, так что слайд, к которому вернулись позже, не сохраняется дважды.
   Кадр — дубль, если средняя разница пикселей меньше `--dedup` (6) **и** меньше 1 % пикселей
   изменились больше чем на 25 уровней. Второе условие сохраняет мелкие изменения текста на белых
   слайдах, которые почти не сдвигают среднее. `--roi 0.75` сравнивает только левые ¾ кадра
   (не учитывает плитки участников в Google Meet).
3. **Обрезка** (`--crop`, или `--meet` = `--roi 0.75 --crop`): кадр обрезается до прямоугольника с
   нетёмными пикселями — это и есть демонстрация экрана.
4. **Сохранение**: `frames/unique/ЧЧ-ММ-СС.jpg` (`_1`, `_2` … если в одну секунду несколько кадров),
   обзорные листы по 20 кадров в `frames/sheets/` и `frames/frames.json` (файл → время) — последним.
5. **OCR**: Apple Vision (точный режим, ru + en, языковая коррекция) по каждому оставленному кадру →
   `ocr/ocr.jsonl`. Модели скачивать не нужно, около 0,2 с на кадр. Новые кадры всегда означают новый
   OCR.

### 6. Склейка

[lib/merge.py](lib/merge.py) читает файлы `asr/*.json` этого запуска (файлы прошлых запусков с другими
опциями не используются), `subs/*.json3`, результаты OCR и `info.json`.

У каждого источника есть язык: `gigaam` — ru, `parakeet` — любой, `<движок>@<язык>` и
`youtube-<вид>@<язык>` — этот язык, остальные движки — единственный язык запуска.

**`aligned.md`**: время делится на окна по 40 с. Каждый сегмент попадает в окно, где лежит его
середина (так ни один сегмент не попадает дважды), подряд идущие повторы убираются, и в каждом окне
стоит текст всех источников плюс текст OCR кадров, показанных в это время. Удобно сверять движки
между собой.

**`transcript.md`** собирается по участкам (без смешанной речи весь файл — один участок):

1. **Основа**: первый источник, чей язык подходит участку, в порядке GigaAM, whisper, parakeet,
   turbo, apple, ручные субтитры YouTube, автосубтитры YouTube, Vosk. Берутся его сегменты, чья
   середина лежит внутри участка, по порядку, без подряд идущих повторов.
2. **Вырезание**: сегменты, которые начинаются внутри диапазона `--cut`, выбрасываются (личные
   разговоры, перерывы).
3. **Подстраховка**, для каждого сегмента основы: если похоже, что движок пропустил речь, сегмент
   заменяется более длинным из текстов parakeet / whisper (того же языка) за тот же промежуток; при
   этом считаются только их сегменты, лежащие внутри хотя бы на 60 %. «Пропустил речь» означает всё
   сразу: меньше 6 символов в секунду (без звуков-пауз), альтернатива длиннее больше чем вдвое и
   длиннее 80 символов, и в альтернативе не больше 25 символов в секунду (иначе это, скорее всего,
   зацикливание).
4. **Чистка**: убираются звуки-паузы (а-а, э-э, ммм, хм, uh, um), применяются замены из глоссария,
   предложения начинаются с заглавной буквы.
5. **Вёрстка**: все участки по времени, абзацы примерно по 55 с с таймкодом, главы YouTube —
   заголовками, а в шапке — языки, число участков, сколько кусков взято из каждого источника на каком
   языке и сколько раз сработала подстраховка.

Текст, пришедший извне (названия и главы YouTube, субтитры, OCR), экранируется перед записью в
Markdown, чтобы он не мог добавить в предпросмотр картинки, ссылки или HTML.

Ещё пишутся `transcript.txt` (по строке `[ЧЧ:ММ:СС] текст` на кусок, без экранирования) и `ocr.md`
(текст с экрана для каждого кадра).

### `vidx find`

[lib/find.py](lib/find.py) ищет регулярное выражение (без учёта регистра) по сегментам всех движков и
строкам OCR и печатает `ЧЧ:ММ:СС  источник  текст` — чтобы перейти к нужной фразе в видео. Третий
аргумент ограничивает поиск одним источником (`gigaam`, `whisper-large-v3@en`, `ocr`, …).

## Глоссарий

`-g ФАЙЛ`, пример — [glossaries/example.txt](glossaries/example.txt):

```
prompt: Созвон команды разработки: Kubernetes, Helm, Kafka, PostgreSQL, Grafana, …
<W>[Кк]афк(а|и|е|у|ой)<E> => Kafka
\b(Graphana|Grafanna)\b => Grafana
```

- `prompt:` передаётся в whisper как `--initial-prompt` — подсказывает, как пишутся термины.
- Строки `регулярка => замена` применяются к итоговой расшифровке (Python `re`). `<W>` и `<E>` —
  границы слова, которые работают и с кириллицей.

В git хранится только `example.txt`; свои глоссарии кладите рядом.

## Папка вывода

| Путь | Что там |
|---|---|
| `transcript.md`, `transcript.txt` | итоговая расшифровка |
| `aligned.md` | все источники и OCR рядом, окна по 40 с |
| `ocr.md` | текст с экрана по кадрам |
| `asr/<движок>[@язык].json` | сырой вывод движков с таймкодами |
| `subs/{manual,auto}.<язык>.json3` | субтитры YouTube |
| `frames/unique/`, `frames/sheets/`, `frames/frames.json` | картинки |
| `ocr/ocr.jsonl` | текст OCR по кадрам |
| `lang.txt`, `regions.json` | определённые языки, языковые участки (смешанная речь) |
| `logs/` | логи задач (`-j > 1`) |
| `.vidx/` | пометка папки, отметки опций, вход, упавшие задачи |
| `audio.wav`, `source.*`, `info.json`, `description.txt`, `thumbnail.jpg` | входные данные |

Код завершения: 0 — всё получилось, 3 — часть задач упала (остальное склеено), 1 — ошибка в опциях
или установке, 130 — прервано.

## Установка

`vidx setup` ставит или обновляет всё нужное и один раз скачивает модели. Запускать повторно
безопасно.

| Где | Что |
|---|---|
| Homebrew | ffmpeg, deno (yt-dlp нужен JS-рантайм для YouTube), uv |
| `uv tool` | mlx-whisper 0.4.3, parakeet-mlx 0.5.3, yt-dlp (последний: старые версии ломаются на YouTube) |
| `.venv` (Python 3.14) | vosk, pillow, numpy (версии закреплены) |
| `.venv-giga` (Python 3.13) | GigaAM на закреплённом коммите, torch, torchaudio, soundfile (версии закреплены) |
| `lib/` | `ocr`, `apple_asr`, собранные из Swift |
| `models/` | vosk-model-ru-0.42 (английская модель скачивается при первом использовании) |
| кэш Hugging Face | whisper-large-v3, whisper-large-v3-turbo, parakeet-tdt-0.6b-v3 |
| `~/.cache/gigaam` | GigaAM v3_e2e_rnnt |

Код на Python работает на версиях 3.11–3.14. GigaAM нужен onnxruntime 1.23, для которого нет сборки
под Python 3.14, поэтому его окружение на 3.13. `VIDX_PYTHON` / `VIDX_PYTHON_GIGA` меняют версии;
удалите `.venv` или `.venv-giga`, чтобы пересоздать окружение. Скрипт работает в bash 5 и в
системном `/bin/bash` 3.2 на macOS.

Модели скачиваются у их авторов и распространяются под своими лицензиями; проверьте их, прежде чем
использовать результат в коммерческих целях. Архивы Vosk скачиваются по HTTPS без проверки
контрольной суммы (авторы её не публикуют).

Сеть используется только yt-dlp, первым скачиванием моделей и короткой проверкой обновлений
Hugging Face при каждом запуске (`HF_HUB_OFFLINE=1` её отключает).
