# vidx

[English](README.md) · **Русский**

Достаёт картинки и текст из видеофайла или ролика YouTube (любой ссылки, которую понимает yt-dlp).
Прогоняет несколько локальных распознавателей речи, распознаёт текст на экране и сводит всё в одну
расшифровку. Всё работает на вашем компьютере (macOS, Linux или Windows): аудио и видео никуда не
отправляются.

Сделан для длинных записей созвонов на русском с демонстрацией экрана. Настроен на 12 языков
(ru, en, de, fr, it, es, ja, zh, hi, be, uk, ar), работает с любым другим языком, который знает whisper,
и с видео, где речь переключается между любым числом языков (`-l uk,en,de`).

```bash
vidx setup                                         # один раз: инструменты + ~13 ГБ моделей
vidx ~/Downloads/meeting.mp4 --meet -j 3           # → ./meeting_vidx-out/transcript.md
vidx "https://www.youtube.com/watch?v=VIDEO_ID" -g glossaries/example.txt
vidx find meeting_vidx-out 'kubernetes|helm'       # фраза → таймкод
vidx help run                                      # все опции
```

Платформы: macOS 26+ на Apple Silicon, Linux (x86_64, arm64) и Windows 10/11 (x86_64), нативно (без WSL);
на Linux и Windows используется видеокарта NVIDIA, если она есть. Команды, опции и файлы вывода везде
одинаковые; движки за ними на разных платформах разные ([Платформы](#платформы)). Установка —
[Установка](#установка).

## Как это работает

```
вход ─► 1 источник ─► 2 аудио ─► 3 язык ─┬─(смешанная речь)─► язык каждого куска ─► участки ─┐
                                         └─────────────────────────────────────────────────┤
                                                                                           ▼
                               очередь задач (-j N):  4 распознаватели речи  │  5 кадры ─► OCR
                                                                                           ▼
                                                                                    6 склейка
```

Каждый шаг пишет результат в папку вывода — по умолчанию `./<имя>_vidx-out/` в текущей папке
(`-o` меняет её). Рядом с каждым результатом vidx сохраняет опции, с которыми он получен
(`.vidx/<файл>.params`). Шаг пропускается, если результат есть **и** получен с теми же опциями, поэтому:

- прерванный запуск продолжается с места остановки: незавершённые шаги не записали отметку и
  выполняются заново;
- смена опции перезапускает только зависящие от неё шаги (`--scene` переделывает кадры и OCR, `-l` —
  движки, привязанные к языку, `-g` — whisper);
- `-f` переделывает всё, включая скачивание.

`.vidx/` ещё и помечает папку как созданную vidx: `-o` откажется писать в непустую папку без этой
пометки, так что vidx никогда не перезапишет и не удалит чужие файлы. Другой входной файл или ссылка
в той же папке — работа начинается заново.

### 1. Источник

- **Локальный файл**: подключается симлинком `source.<ext>`, не копируется. Если система не разрешает
  симлинки (Windows без режима разработчика), vidx читает файл на месте и пишет об этом.
- **Ссылка**: yt-dlp скачивает видео (≤ 1080p, `--max-height`), `info.json` (название, главы, язык),
  `description.txt` и `thumbnail.jpg`. Из ссылки на плейлист берётся только одно видео; конфиги
  yt-dlp игнорируются (`--ignore-config`).
- **Субтитры YouTube**: ещё два прохода yt-dlp — отдельно ручные и автоматические, чтобы они попали в
  разные файлы (`subs/manual.ru.json3`, `subs/auto.en.json3`). Запрашиваются только дорожки на языке
  оригинала: ru, en, языки из `--lang` и язык самого видео, плюс их варианты `-orig`. Без этого
  списка YouTube отдаёт десятки машинных переводов. `--sub-langs` задаёт список вручную.
  Для видео на двух языках скачиваются обе дорожки, ru и en, если они есть. Но автосубтитры YouTube
  делаются только на одном языке (основном языке видео), поэтому второй язык в них искажён; при
  склейке каждая дорожка используется только на участках своего языка, остальное закрывают
  распознаватели речи.

### 2. Аудио

ffmpeg → `audio.wav`, 16 кГц, моно, 16-битный PCM — формат, который ждут все движки. Файл сначала
пишется под временным именем и переименовывается, когда готов. Если в файле нет звуковой дорожки,
работа останавливается с понятным сообщением; `--no-asr` пропускает шаги 2–4 и даёт только картинки
и OCR.

### 3. Язык

`--lang` принимает `auto`, один язык (`ru`) или список любой длины (`ru,en`, `uk,en,de`). Повторы
убираются. У каждого языка одна строка в [languages.py](src/vidx/lib/languages.py); см. [Языки](#языки).

`auto` ([detect_lang.py](src/vidx/lib/detect_lang.py)): whisper turbo определяет язык равномерно
разнесённых 10-секундных отрывков, по одному на минуту записи (от 5 до 30 отрывков). Самый частый язык
берётся всегда; ещё один — только если он выиграл хотя бы 2 отрывка **и** 20 % от всех, чтобы одна
ошибка не делала видео смешанным. Если речи нет вовсе — `ru`. Результат кэшируется в `lang.txt`.
Поэтому короткие видео и короткие переключения (один вопрос на английском посреди русского созвона)
смешанными не определяются: укажите `-l ru,en` явно.

Русская речь с английским жаргоном (Kubernetes, деплой, Jenkins) — **не** смешанная: используйте
`ru` и глоссарий. Смешанная — это целые куски на разных языках.

**Языковые участки (только для смешанной речи).** Движки, которым задан язык, плохо работают на
других: whisper с `--language en` *переводит* русскую речь на английский, а GigaAM превращает
английскую речь в бессмыслицу латиницей. Поэтому до очереди задач [regions.py](src/vidx/lib/regions.py)
делит аудио на участки одного языка → `regions.json` (`[{start, end, lang}]`):

1. **Куски**: аудио режется посередине каждой паузы; куски короче 2 с присоединяются к соседу за более
   короткой паузой (более длинная пауза — вероятнее смена языка), куски длиннее 8 с дорезаются в самых
   тихих местах.
2. **Язык каждого куска** ([lid.py](src/vidx/lib/lid.py), whisper turbo): вероятность каждого языка из
   списка, нормированная по списку. Определяется по звуку, а не по буквам расшифровки, поэтому работает
   для любого числа языков и для пар с одним алфавитом (ru/uk, de/fr).
3. **Сглаживание**: кусок короче 2 с или с уверенностью ниже 60 % берёт язык соседей; соседи с
   одним языком сливаются в участки; участок короче 3 с присоединяется к соседу, к которому склоняются
   его куски.
4. **Уточнение границ**: кусок у границы может содержать конец одного языка и начало другого. Он
   режется по самой длинной внутренней паузе, и граница сдвигается туда, если часть у границы — на
   другом языке.
5. **Притягивание**: если parakeet запускался (только когда он знает все языки из списка), каждая
   граница сдвигается к ближайшей паузе между его предложениями в пределах 1,5 с.
6. Предупреждение, если два языка из списка не удалось надёжно различить.

Результаты на тестовых клипах (голоса macOS): uk → en → de дал три участка, границы (6,1 с и 11,3 с)
попали в середину пауз на двух сменах языка; ru → uk и de → fr — в пределах 0,15 с от смены. На Linux
(faster-whisper, даже с моделью tiny) границы uk → en → de и ru → en → ru совпали с macOS в пределах
0,25 с. Если разбиение падает, работа продолжается только с первым языком из списка.

### 4. Распознаватели речи (очередь задач)

Каждый движок пишет `asr/<имя>.json` — список сегментов `{start, end, text}`. Движки запускаются только
для своих языков (таблица в разделе [Языки](#языки)). При смешанной речи движки, которым задаётся язык,
запускаются по разу на каждый язык, которому достался участок, и получают суффикс `@язык`
(`whisper-large-v3@en`); whisper и turbo при этом распознают только участки своего языка
(`--clip-timestamps`), GigaAM — только русские участки. Vosk и Apple работают по всему файлу; при
склейке их текст вне своего языка не используется.

| Движок | Модель | Язык | Заметки |
|---|---|---|---|
| whisper | whisper-large-v3 | задаётся, по разу на язык | подсказка из глоссария, `--condition-on-previous-text False` против зацикливания |
| vosk | Kaldi vosk-model-&lt;язык&gt; | по разу на язык, для которого есть модель | CPU; модели скачиваются при первом использовании (0,3–1,9 ГБ каждая); примерно в реальном времени |
| gigaam | GigaAM-v3 e2e_rnnt (Сбер) | только русский | см. ниже |
| parakeet | parakeet-tdt-0.6b-v3 | его 25 европейских языков, язык не задаётся | на других языках пишет бессмыслицу латиницей, поэтому там не запускается; при смешанной речи запускается первым, и по краям его предложений уточняются участки |
| apple | macOS SpeechTranscriber | по разу на поддерживаемый язык, локаль задаётся явно (de → de-DE) | только macOS; русского нет; модель для каждой локали скачивается при первом использовании, на это даётся `VIDX_APPLE_TIMEOUT` секунд (по умолчанию 300, максимум 86400) |
| turbo | whisper-large-v3-turbo | задаётся, по разу на язык | запасной вариант whisper |

Какая программа исполняет движок, зависит от платформы ([Платформы](#платформы)); файлы вывода и их
JSON везде одинаковые. `VIDX_MODEL_WHISPER`, `VIDX_MODEL_TURBO` (на нём же определяется язык),
`VIDX_MODEL_PARAKEET` и `VIDX_VOSK_<ЯЗЫК>` (например, `VIDX_VOSK_RU=vosk-model-small-ru-0.22`) заменяют
модель — например, на машине без видеокарты.

**GigaAM** не принимает аудио длиннее 25 с, поэтому [gigaam_run.py](src/vidx/lib/gigaam_run.py) режет его
сам: меряет громкость каждого 30-миллисекундного кадра, режет в самом тихом месте через 14–22 с после
предыдущего разреза и так до конца; тихие куски пропускаются, каждый кусок распознаётся отдельно. При
смешанной речи режется каждый русский участок отдельно, так что ни один кусок не пересекает смену
языка. Кусок с ошибкой пропускается; если упали все — движок считается упавшим. Считает на видеокарте
NVIDIA (CUDA), иначе на видеокарте Apple (MPS), иначе на CPU (`VIDX_GIGAAM_DEVICE` задаёт явно).

**Vosk** ([vosk_run.py](src/vidx/lib/vosk_run.py)) получает аудио порциями по 0,5 с и сохраняет сегмент
каждый раз, когда Kaldi закрывает фразу.

**Параллельный запуск.** `-j N` выполняет до N задач одновременно (по умолчанию 1 — по очереди).
Очередь устроена так, что работа на GPU и CPU чередуется: whisper (GPU) · vosk (CPU) · кадры + OCR
(CPU) · gigaam · parakeet · apple · turbo. Поэтому уже `-j 2` совмещает самые долгие задачи на GPU и
CPU, а `-j 3` добавляет кадры. При `-j > 1` вывод каждой задачи идёт в `logs/<задача>.log`, а в
терминале видны только старт, завершение и ошибки (с последними строками лога). При смешанной речи
parakeet и разбиение на участки выполняются до очереди: GigaAM и whisper нужны участки. Ctrl-C
(Ctrl-Break на Windows), закрытие терминала (macOS, Linux) или непредвиденная ошибка останавливает все
запущенные задачи вместе с процессами, которые они запустили; повторный Ctrl-C во время остановки
игнорируется.

Упавшая задача не останавливает работу: остальное склеивается, упавшие задачи перечисляются в конце,
и vidx завершается с кодом 3.

Ограничение — память: whisper large-v3 нужно около 4 ГБ, Vosk ru — около 6 ГБ RAM, parakeet и turbo —
по 2–3 ГБ, GigaAM — около 1 ГБ. На машине с 24 ГБ комфортно `-j 3`, на 16 ГБ — `-j 2`.

### 5. Кадры и OCR (очередь задач)

Одна задача, [frames.py](src/vidx/lib/frames.py) и программа OCR ([ocr.swift](src/vidx/lib/ocr.swift) на
macOS, [ocr_rapid.py](src/vidx/lib/ocr_rapid.py) на остальных):

1. **Захват**: один проход ffmpeg сохраняет кадр, когда сцена меняется сильнее `--scene` (0,3) или
   когда с последнего сохранённого кадра прошло `--every` секунд (10). Время каждого кадра даёт
   фильтр ffmpeg `showinfo`. Сырые кадры складываются во временную папку.
2. **Отсев дублей**: каждый кадр уменьшается до серой миниатюры 240×135 и сравнивается с 6
   последними оставленными кадрами, так что слайд, к которому вернулись позже, не сохраняется дважды.
   Кадр — дубль, если средняя разница пикселей меньше `--dedup` (6) **и** меньше 1 % пикселей
   изменились больше чем на 25 уровней. Второе условие сохраняет мелкие изменения текста на белых
   слайдах, которые почти не сдвигают среднее. `--roi 0.75` сравнивает только левые ¾ кадра
   (не учитывает плитки участников в Google Meet).
3. **Обрезка** (`--crop`, или `--meet` = `--roi 0.75 --crop`): кадр обрезается до прямоугольника с
   нетёмными пикселями — это и есть демонстрация экрана.
4. **Сохранение**: `frames/unique/ЧЧ-ММ-СС.jpg` (`_1`, `_2` … если в одну секунду несколько кадров),
   обзорные листы по 20 кадров в `frames/sheets/` и `frames/frames.json` (файл → время) — последним.
5. **OCR** по каждому оставленному кадру → `ocr/ocr.jsonl`, для языков запуска плюс английский
   (be → ru + uk).
   - macOS: Apple Vision (точный режим, языковая коррекция). Vision читает только алфавит первого языка
     запроса, поэтому для каждого алфавита (латиница/кириллица, CJK, арабский, деванагари) идёт свой
     запрос, а строки объединяются по положению на кадре. Модели скачивать не нужно, около 0,2 с на кадр
     и алфавит.
   - Linux, Windows: RapidOCR (распознаватели PP-OCRv5 на onnxruntime, ~10 МБ на алфавит, скачиваются при
     первом использовании в `models/rapidocr/`). Те же группы алфавитов сопоставлены его моделям (eslav
     для русского/украинского/белорусского, latin, ch для китайского и японского, arabic, devanagari,
     korean); если одну строку прочли две модели, остаётся та, чей текст на её собственном алфавите.
     Известный пробел: заголовки на деванагари (хинди) не находятся; кириллические буквы, похожие на
     латинские, иногда читаются латиницей.

   Новые кадры всегда означают новый OCR. Подписи на обзорных листах — Arial Bold на macOS и встроенный
   шрифт Pillow на остальных.

### 6. Склейка

[merge.py](src/vidx/lib/merge.py) читает файлы `asr/*.json` этого запуска (файлы прошлых запусков с другими
опциями не используются), `subs/*.json3`, результаты OCR и `info.json`.

У каждого источника есть язык: `gigaam` — ru, `parakeet` — любой из его 25, `<движок>@<язык>` и
`youtube-<вид>@<язык>` — этот язык, остальные движки — единственный язык запуска. Каждый участок
использует строку своего языка из таблицы: пороги, разделитель, звуки-паузы.

**`aligned.md`**: время делится на окна по 40 с. Каждый сегмент попадает в окно, где лежит его
середина (так ни один сегмент не попадает дважды), подряд идущие повторы убираются, и в каждом окне
стоит текст всех источников плюс текст OCR кадров, показанных в это время. Удобно сверять движки
между собой.

**`transcript.md`** собирается по участкам (без смешанной речи весь файл — один участок):

1. **Основа**: первый источник, чей язык подходит участку, в порядке GigaAM, whisper, parakeet,
   turbo, apple, ручные субтитры YouTube, автосубтитры YouTube, Vosk. Берутся его сегменты, чья
   середина лежит внутри участка, по порядку, без подряд идущих повторов.
2. **Вырезание**: сегменты, которые начинаются внутри диапазона `--cut`, выбрасываются (личные
   разговоры, перерывы).
3. **Подстраховка**, для каждого сегмента основы: если похоже, что движок пропустил речь, сегмент
   заменяется самой длинной альтернативой за тот же промежуток; считаются только сегменты, лежащие
   внутри хотя бы на 60 %. Альтернативы — parakeet и whisper; если parakeet язык не знает — whisper,
   turbo и Apple. «Пропустил речь» означает всё сразу:
   - символов в секунду меньше нижней границы языка (без звуков-пауз): 6 для ru/en/uk/be, 7 для
     de/fr/it/es, 3 для ar, 2,5 для ja, 2 для zh;
   - альтернатива длиннее больше чем вдвое и не короче 5 с обычной речи на этом языке (80 символов для
     ru/en, 22,5 для zh);
   - альтернатива не быстрее предела зацикливания (25 для ru/en, 10 для zh), иначе это, скорее всего,
     зацикливание.
4. **Чистка**: убираются звуки-паузы языка (а-а, э-э, ммм, хм, uh, um, äh, euh, えー, 呃, …; слова вроде
   немецкого «um» или белорусского «ем» остаются), применяются замены из глоссария, предложения
   начинаются с заглавной буквы в любом алфавите. Куски соединяются пробелом, а для китайского,
   японского, тайского, лаосского, бирманского и кхмерского — без пробела.
5. **Вёрстка**: все участки по времени, абзацы примерно по 55 с с таймкодом, главы YouTube —
   заголовками, а в шапке — языки, число участков, сколько кусков взято из каждого источника на каком
   языке и сколько раз сработала подстраховка.

Текст, пришедший извне (названия и главы YouTube, субтитры, OCR, вывод движков), экранируется перед
записью в Markdown: никаких картинок, ссылок (в том числе с вложенными скобками или обратной косой
чертой), HTML, кода и блоков (перенос строки внутри названия не создаст заголовок). Обычная пунктуация
вроде `!` или `[черновик]` остаётся читаемой.

Ещё пишутся `transcript.txt` (по строке `[ЧЧ:ММ:СС] текст` на кусок, без экранирования) и `ocr.md`
(текст с экрана для каждого кадра).

### `vidx find`

[find.py](src/vidx/lib/find.py) ищет регулярное выражение (без учёта регистра) по сегментам всех движков и
строкам OCR и печатает `ЧЧ:ММ:СС  источник  текст` — чтобы перейти к нужной фразе в видео. Третий
аргумент ограничивает поиск одним источником (`gigaam`, `whisper-large-v3@en`, `ocr`, …).

## Глоссарий

`-g ФАЙЛ`, пример — [glossaries/example.txt](glossaries/example.txt):

```
prompt: Созвон команды разработки: Kubernetes, Helm, Kafka, PostgreSQL, Grafana, …
<W>[Кк]афк(а|и|е|у|ой)<E> => Kafka
\b(Graphana|Grafanna)\b => Grafana
```

- `prompt:` передаётся в whisper как `--initial-prompt` — подсказывает, как пишутся термины.
- Строки `регулярка => замена` применяются к итоговой расшифровке (Python `re`). `<W>` и `<E>` —
  границы слова, которые работают и с кириллицей.

В git хранится только `example.txt`; свои глоссарии кладите рядом.

## Языки

У каждого языка одна строка в [languages.py](src/vidx/lib/languages.py): алфавит, локаль Apple, языки OCR,
модель Vosk, знает ли его parakeet, разделитель, звуки-паузы и пороги склейки. Код не из таблицы
(любой другой язык whisper) получает настройки «только whisper» для своего алфавита.

| Язык | whisper, turbo | parakeet | GigaAM | Apple ASR (macOS) | Модель Vosk | OCR (локаль Vision) |
|---|---|---|---|---|---|---|
| ru | ✓ | ✓ | ✓ | – | ru-0.42 | ru-RU |
| en | ✓ | ✓ | – | en-US | en-us-0.22 | en-US |
| de, fr, it, es | ✓ | ✓ | – | de-DE, fr-FR, it-IT, es-ES | de-0.21, fr-0.22, it-0.22, es-0.42 | ✓ |
| uk | ✓ | ✓ | – | – | uk-v3 | uk-UA |
| ja, zh | ✓ | – | – | ja-JP, zh-CN | ja-0.22, cn-0.22 | ja-JP, zh-Hans |
| hi | ✓ | – | – | hi-IN | hi-0.22 | hi-IN |
| ar | ✓ | – | – | – | ar-mgb2-0.4 | ar-SA |
| be | ✓ | – | – | – | – | через ru-RU + uk-UA |

Проверено на коротких клипах голосами macOS: автоопределение и расшифровка верны для de, fr, it, es,
ja, zh, hi, uk и ar (macOS). Для **белорусского** голоса нет, он покрыт только юнит-тестами; его знают только
whisper и turbo, так что качество будет самым низким. Пороги подобраны на синтезированной речи, она
чище и быстрее реальных созвонов; для русского остались значения, подобранные на реальных записях.

## Платформы

Конвейер, опции, файлы вывода и их форматы на всех платформах одинаковые. Каждый движок — программа с
одной и той же командной строкой на любой ОС (см. [engines.py](src/vidx/engines.py)); исполняет её:

| Движок | macOS (Apple Silicon) | Linux, Windows |
|---|---|---|
| whisper, turbo | mlx-whisper (видеокарта Apple) | faster-whisper (CTranslate2): видеокарта NVIDIA с CUDA 12 (float16), иначе CPU (int8) |
| определение языка (auto, смешанная речь) | whisper turbo, mlx-whisper | whisper turbo, faster-whisper |
| parakeet | parakeet-mlx (видеокарта Apple) | onnx-asr + Silero VAD: CUDA, DirectML (Windows, по запросу) или CPU (int8) |
| gigaam | PyTorch на MPS | PyTorch на CUDA или CPU |
| apple | SpeechTranscriber (Neural Engine) | недоступен: пропускается с сообщением, это не ошибка |
| vosk | Kaldi (CPU) | Kaldi (CPU) |
| OCR | Apple Vision | RapidOCR (onnxruntime, CPU) |

Разные реализации одной модели дают немного разный текст; пороги склейки подбирались на выводе macOS.
`vidx setup` сообщает, на чём будет считать каждый движок. На машине без видеокарты NVIDIA движки
считают на CPU: whisper large-v3 там будет медленным, попробуйте `VIDX_MODEL_WHISPER=large-v3-turbo`.

Что где проверено (2026-10-11; Windows — 2026-10-16):

| | macOS (Apple Silicon) | Linux (контейнер, arm64, CPU) | Windows (GitHub Actions, x64, CPU) |
|---|---|---|---|
| юнит- и CLI-тесты (фальшивые движки) | ✓ Python 3.11, 3.14 | ✓ Python 3.11, 3.13 | ✓ Python 3.11, 3.14 (`ci`) |
| тесты с настоящими движками (`-m real`) | ✓ | ✓ с маленькими моделями | ✓ с маленькими моделями (`smoke`) |
| полные запуски на тестовых клипах | ✓ те же файлы, что у bash-версии | ✓ | ✓ `ru_en.m4a`, `ru_slides.mp4` (`smoke`) |
| `vidx setup` | пробный прогон | ✓ (`--no-models`) | ✓ (`--no-models`, `smoke`) |
| видеокарта NVIDIA | — | здесь недоступна | не запускалась |

На Windows vidx пока запускался только на машинах GitHub, не на обычном компьютере: Ctrl-C руками в
консоли, симлинки в режиме разработчика, NVIDIA и папка пользователя не латиницей ещё ждут проверки по
списку из [docs/plans/2026-10-11-porting-analysis.md](docs/plans/2026-10-11-porting-analysis.md).

## Установка

Самому vidx нужны только Python 3.11+ и [uv](https://docs.astral.sh/uv/); окружения движков создаёт
`vidx setup`. Он проверяет ffmpeg (с ffprobe), deno (JS-рантайм, нужный yt-dlp для YouTube) и uv и
печатает команду, которая поставит недостающее; сам пакетные менеджеры не запускает.

**macOS** (из клона; нужны Xcode command line tools для `swiftc`):

```bash
brew install ffmpeg deno uv
git clone https://github.com/DmitriiRus37/vidx && cd vidx
./vidx setup                                  # ~13 ГБ моделей
ln -s "$PWD/vidx" ~/.local/bin/vidx           # чтобы вызывать из любой папки (любая папка из PATH)
```

**Linux** (Debian/Ubuntu; Fedora: `sudo dnf install ffmpeg-free` или полный ffmpeg из RPM Fusion):

```bash
sudo apt install ffmpeg
curl -fsSL https://deno.land/install.sh | sh
curl -LsSf https://astral.sh/uv/install.sh | sh
uv tool install git+https://github.com/DmitriiRus37/vidx     # или в клоне: uv tool install -e .
vidx setup
```

**Windows** (PowerShell; после установки откройте новый терминал):

```powershell
winget install --id Gyan.FFmpeg -e
winget install --id DenoLand.Deno -e
winget install --id astral-sh.uv -e
uv tool install git+https://github.com/DmitriiRus37/vidx
uv tool update-shell
vidx setup
```

Клон работает и на Linux через `./vidx` (запускалку), как на macOS. `vidx setup --dry-run` показывает,
что будет сделано; `--no-models` не скачивает модели; `--gpu cuda|directml|cpu` задаёт видеокарту явно
(по умолчанию сборки с CUDA, если `nvidia-smi` находит видеокарту NVIDIA).

Что ставит `vidx setup` (запускать повторно безопасно; существующие окружения сохраняются, окружение,
у которого пропал Python, пересоздаётся; удалите окружение, чтобы пересоздать его):

| Где | macOS | Linux, Windows |
|---|---|---|
| `uv tool` | mlx-whisper 0.4.3, parakeet-mlx 0.5.3, yt-dlp | yt-dlp (последний: старые версии ломаются на YouTube) |
| `.venv` (Python 3.14) | vosk, pillow, numpy, psutil (версии закреплены) | то же |
| `.venv-giga` (Python 3.13) | GigaAM на закреплённом коммите, torch, torchaudio, soundfile | то же; torch из индекса PyTorch для CPU или CUDA 12.6 |
| `.venv-whisper` (Python 3.13) | — | faster-whisper, CTranslate2, RapidOCR, onnxruntime |
| `.venv-onnx` (Python 3.13) | — | onnx-asr с onnxruntime (CPU), onnxruntime-gpu (CUDA 12) или onnxruntime-directml |
| `bin/` | `ocr`, `apple_asr`, собранные из Swift | — |
| `models/` | vosk-model-ru-0.42 (модели других языков скачиваются при первом использовании) | то же и `rapidocr/` |
| кэш Hugging Face | whisper-large-v3, whisper-large-v3-turbo, parakeet-tdt-0.6b-v3 (MLX) | версии для faster-whisper и ONNX |
| `~/.cache/gigaam` | GigaAM v3_e2e_rnnt | то же |

Всё это лежит в **папке vidx**: в клоне, если vidx запущен из него, иначе в `~/Library/Application
Support/vidx`, `~/.local/share/vidx` (или `$XDG_DATA_HOME/vidx`) или `%LOCALAPPDATA%\vidx`; `VIDX_HOME`
задаёт её явно. `.venv` и `.venv-giga` — два окружения, потому что GigaAM нужен onnxruntime 1.23, для
которого нет сборки под Python 3.14; `.venv-whisper` и `.venv-onnx` — два, потому что faster-whisper
требует onnxruntime для CPU, а он перезаписал бы версию для видеокарты. `VIDX_PYTHON`,
`VIDX_PYTHON_GIGA` и `VIDX_PYTHON_ENGINES` меняют версии Python.

**Видеокарта NVIDIA на Linux и Windows.** faster-whisper нужен CUDA 12 с cuBLAS (Linux: CUDA toolkit
или пакет `nvidia-cublas-cu12`; Windows: CUDA 12 toolkit или DLL cuBLAS в `PATH`); без них он пишет об
этом и считает на CPU. torch и onnxruntime-gpu приносят свои библиотеки CUDA. `VIDX_WHISPER_DEVICE`,
`VIDX_ONNX_PROVIDER` и `VIDX_GIGAAM_DEVICE` задают устройство явно.

Модели скачиваются у их авторов и распространяются под своими лицензиями; проверьте их, прежде чем
использовать результат в коммерческих целях. Архивы Vosk скачиваются по HTTPS без проверки
контрольной суммы (авторы её не публикуют).

Сеть используется только yt-dlp, первым скачиванием моделей и короткой проверкой обновлений
Hugging Face при каждом запуске (`HF_HUB_OFFLINE=1` её отключает).

## Разработка

Тесты пишутся первыми (TDD) и по умолчанию не требуют моделей:

```bash
uv run --isolated --group test pytest                       # юнит- и CLI-тесты, ~1,5 мин, без моделей и сети
uv run --isolated --group test --python 3.11 pytest         # самый старый поддерживаемый Python
HF_HUB_OFFLINE=1 uv run --isolated --group test pytest -m real   # с настоящими моделями (после vidx setup)
uvx ruff check src/ tests/
sh -n vidx                                                  # POSIX-запускалка
```

- `--isolated` не даёт uv ставить пакеты в `.venv` — это собственное окружение vidx.
- **Фальшивые движки**: с `VIDX_FAKE_ENGINES=1` vidx подключает `tests/fakes/hook.py`, который
  подменяет программу каждого движка на `tests/fakes/engine.py` (та же командная строка, заготовленный
  результат), поэтому очередь задач, отметки, продолжение, `-j`, ошибки и Ctrl-C проверяются целиком
  за секунды. `VIDX_FAKE_PLATFORM` (darwin, linux, win32) даёт запуску движки другой платформы; так
  проверяются ветки кода только для Windows (группы процессов, `Scripts\python.exe`, запрет симлинков,
  кодовые страницы), а нативно — на Windows-машине CI.
- **Эталоны**: `tests/golden/` хранит ожидаемые расшифровки; `VIDX_UPDATE_GOLDENS=1` перезаписывает их
  после осознанного изменения (проверьте diff).
- **Фикстуры**: короткие клипы голосами macOS, отрисованные слайды и вывод движков в `tests/fixtures/`
  (до 400 КБ каждый).
- **CI** ([.github/workflows](.github/workflows)): `ci.yml` запускает ruff и тесты на macOS, Linux и
  Windows с Python 3.11 и 3.14, а также ещё раз тесты на Linux в локали Latin-1 с выключенным режимом
  UTF-8 (`latin-1`); `smoke.yml` (по ночам и вручную) запускает `vidx setup` и настоящие
  движки с маленькими моделями на Linux и Windows.
- Текстовые файлы — UTF-8 с LF на любой ОС: каждый `open()` указывает кодировку и перевод строки, а
  каждое чтение вывода программы как текста — кодировку (это проверяет тест). Таков же вывод vidx,
  перенаправленный в файл или канал, при любой локали, и сообщения скриптов в логах `-j`; терминал
  сохраняет свою кодировку и показывает символ, которого в ней нет, как `?`, в том числе в сообщениях
  движков. Текстовые аргументы (подсказка из глоссария, регулярное выражение `vidx find`, URL) доходят до
  программ в UTF-8 при любой локали; имена файлов передаются так, как их дала ОС.
- Планы и анализ переноса — в [docs/plans/](docs/plans/).
